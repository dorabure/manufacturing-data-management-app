# 操作説明 Ver1.10

本書は製造業向け 業務データ管理アプリ Ver1.10の操作説明です。本番導入前に、実SCADAでCSVの公開方式を確認してください。推奨は「.tmpへ書く → 完成してClose → .csvへrename」です。直接.csvへ書く装置では、完成まで書込みハンドルを保持してください（詳しくは本書の「6. 書込み中CSVと公開方式」）。また、利用PCの100%／125%／150%表示倍率で、文字・入力欄・ボタンに表示切れがないことを確認してください。

## 1. 準備と基本操作

DBは `%LocalAppData%\ManufacturingDataApp\ManufacturingDataApp.db` に保存します。Ver1.00 DBはバックアップ後にMigrationし、データ・設定・マスタ・ログ・IDを保持します。未知／不完全なDBは自動修復しません。失敗時に原本を削除しないでください。

1. 「CSV設定」で文字コード・区切り文字・ヘッダー有無・標準6項目の列番号を設定します。
2. 「マスタ管理」で設備と測定項目を準備します。必要なら測定項目の最小値／最大値を指定します。
3. メイン画面でCSV設定を選択します。監視設定もこの設定ごとに独立しています。

架空データ例（実際には選択したCSV設定に合わせます）：

```csv
取得日時,設備ID,設備名,項目名,測定値,単位
2026-09-21T09:00:00.0000000Z,EQ001,搬送装置01,温度,25.3,℃
```

## 2. 取込方法の違い

| 項目 | 1ファイル取込 | フォルダ周期監視 |
|---|---|---|
| 操作 | CSV取込でファイル選択 | フォルダ・周期を保存して開始 |
| 正常3行＋異常2行 | 正常3行登録、結果5/3/2 | DB0行、結果5/0/5。不正2行・正常保留3行 |
| 登録方針 | 正常行のみ | All-or-Nothing：ファイル全件登録または全件未登録 |
| 完了後 | 手動でファイル管理 | success／errorへ移動しJournalで記録 |

保存モードではなく実行した入口で登録方針が決まります。周期用設定でも手動入口では部分登録です。

## 3. 周期監視を始める

1. CSV設定を選んで「フォルダ周期監視」を選びます。
2. 監視フォルダにローカルの通常フォルダを指定します。UNC、SMB、NAS、ネットワーク割当ドライブ、junction等は使用できません。
3. 周期秒に1～604800の整数を指定します（7日まで）。
4. 「監視設定保存」を押し、開始します。形式・列対応は監視設定保存で変わりません。

準備後に初回を直ちに実行し、以後は固定周期です。処理中に次の周期が来ても並列実行せず、その周期をスキップします。遅れた分を連続実行しません。

設定保存・修正版確認・アプリ再起動だけでは自動開始しません。起動時は必ずStoppedです。未保存でCSV設定を切り替える場合は保存／破棄／取消を選びます。保存失敗時は開始や切替をせず入力を確認します。手動モードへ変更しても監視フォルダ値は保持します。

取込後の一覧は自動検索しないため、最新データを見るときは「検索」を押してください。

## 4. 現在状態と履歴

| 状態 | 意味 |
|---|---|
| Stopped | 停止。異常理由の解消が必要な場合があります |
| Starting | 開始準備中 |
| Running | 監視中。CSVなし／書込み待ちも含みます |
| Stopping | 現在CSVの処理・記録・移動・後片付けの完了待ち |

現在状態と過去の履歴は別表示です。履歴選択で現在状態は変わりません。履歴は最大100件、通知文は最大512文字、同種スキップは集約します。通常スキップを毎回DBログには保存しません。

開始準備・監視・停止待ち中は、モード変更、手動取込、CSV設定選択／編集、監視設定変更、詳細編集、削除、マスタ変更ができません。検索・ログ閲覧・CSV出力は利用できます。イベント入口でも禁止操作を防止します。

## 5. フォルダと順序

| 場所 | 用途 |
|---|---|
| 監視フォルダ直下 | 公開済み.csv／.CSV等。サブフォルダは走査しません |
| success | 正常CSV。空／ヘッダーのみも正常0件として移動 |
| error | 解析・行検証で拒否されたCSV。DB障害はここへ移しません |
| .periodic-import | Order（順番）、Attempt（処理記録）、Journal、修正版対応付け等 |

**`.periodic-import`を削除・編集しないでください。** 二重登録防止の根拠を失います。管理記録の痕跡なき削除を完全に検出する保証はありません。

最初に更新日時と同時刻のファイル名順で順番を確定・保存します。先頭が書込み中なら後続も処理しません。先頭の更新日時が新しくなっても、停止・再起動を挟んでも保存順を優先します。途中で届いた古い日時のCSVも既存Orderを追い越しません。

移動先が同名でも上書きせず別名にします。`owner.lock`は同じRootの二重監視防止用です。ファイルの存在ではなく実ハンドル所有で使用中を判断します。手作業で削除しないでください。

## 6. 書込み中CSVと公開方式

推奨は「.tmpへ書く → 完成してClose → .csvへrename」です。.tmpは対象外です。

直接.csvへ書く場合は、完成まで書込みハンドルを保持し、最後にCloseしてください。アプリは読取りガードを取得できるまでWaitingForReadableで保留します。サイズや更新時刻の安定だけでは完成扱いしません。

途中でCloseして後で追記する装置では、未完成でも取込できる隙間が生じます。安全だと推測せず、tmp→rename等の公開契約を担当者と確定してください。実SCADAは今回未検証です。

## 7. Validationエラーと修正版

A正常、B異常、C正常では、Aはsuccess、BはDB0件でerror、Cは未処理のまま停止します。CorrectionPendingは「元のBの位置で修正版の確認待ち」です。

1. ログで問題を確認し原本を保全して、修正版B2を監視Rootに置きます。
2. 停止中に修正版確認画面を開き、対象の失敗と候補を確認します。同名だけで自動対応付けしません。
3. 候補を選び、内容・対応関係を確認して確定します。
4. 保存後も自動開始しません。ユーザーが改めて開始します。

B2の更新日時がCより新しくてもB2→Cです。B2が再失敗すると再び停止し、元BとB2の履歴を保持してCを保留します。

確認済み候補や設定を変更したら再確認が必要です。「確認し直し」は旧対応付けを先に無効化します。新確認が失敗しても旧対応付けに戻らず停止したままです。元の形式設定を復元して確認してください。後続Cや成功済み・別未解決処理のCSVを流用しないでください。

## 8. RecoveryRequired／MovePendingと保全

RecoveryRequiredは登録結果や管理情報を安全に判断できず、人の確認が必要な状態です。DB接続・検索・登録障害、UNIQUE／FK、locked、Commit結果不明、Journal破損、指紋不一致等は行エラーとは異なります。

**「きっと0件だった」と推測して再取込、修正版指定、DBや管理記録の削除をしないでください。** 元CSVと後続を保留し自動再実行を禁止しています。

MovePendingは結果記録後の移動未完了です。DB登録済みの可能性があります。再開始時はJournalに基づく移動のみ復旧し、再登録しません。復旧後は停止して結果を確認し、必要ならユーザーが再開始します。元と移動先の両方がある／両方ない／指紋不一致では自動推測しません。

保全手順：

1. 担当者と新規CSV供給停止を調整し、安全停止を待ちます。本番設備を無断操作しないでください。
2. 元CSV・success・error・.periodic-import・DB・ログを同じ時点の一式として保全します。
3. DB利用プロセス停止を確認し、SQLiteのWAL等も考慮した整合バックアップを取得します。稼働中DB本体だけをコピーしないでください。
4. 管理者とDB件数・対象データ・Attempt・指紋・移動先を照合します。復元はDB／CSV／Journalの整合を確認して実施します。

DBだけの差替えを自動検出する保証はありません。判断不能なら現状を維持し、保全情報を開発者へ渡してください。

## 9. 検索・編集・削除・出力・ログ

設備ID・項目名・取得日で検索します。日付チェックを外すとその境界は指定なし、終了日を指定すると当日終日を対象にします。「条件クリア」で条件を外して検索します。

一覧の測定日時・設備ID・設備名・項目名・測定値・単位は直接編集できません。停止中に行をダブルクリックして詳細画面から編集します。選択チェックボックスのみ変更可能で、選択IDを複数削除できます。CSV出力は現在の検索結果と選択CSV設定を使用します。

エラーログ／操作ログも条件指定で検索できます。日付未指定なら日付で絞りません。監視中の結果を見るときも再検索してください。

## 10. 安全停止と終了

停止操作や×は現在CSVの安全完了を待ちます。後続は開始しません。×を連打しても停止を多重実行しません。長時間待機の案内は強制終了の許可ではありません。

後片付けに失敗すると画面を残してエラーを表示します。タスク終了で強制的に閉じず理由を確認してください。再起動後も自動開始しません。

## 11. 困ったとき

| 症状 | 対応 |
|---|---|
| 開始できない | 設定選択・保存結果・モード・フォルダ・整数周期・他の所有者を確認 |
| 先頭から進まない | 書込みハンドルと公開契約を確認。後続を追越しさせない |
| 一覧が増えない | 再検索、日付条件、状態・ログを確認 |
| CorrectionPending | 修正版を明示確認後に手動開始 |
| RecoveryRequired | CSV・DB・管理領域保全。推測再登録禁止 |
| MovePending | 移動先容量・権限等を確認。手動再投入禁止 |
| 終了待ちが長い | I/Oと現在CSV完了を待つ。1000小CSV実測約82.9分で、運用性能は別評価 |

本番導入前に、隔離した試験環境で実SCADAのCSV公開方式を確認してください。装置の「完成」の意味をアプリだけでは保証できないため、tmp→rename方式を推奨します。直接.csvへ書く装置では、完成まで書込みハンドルを保持することを確認してください。利用PCの100%／125%／150%表示倍率で、文字・入力欄・ボタンに表示切れがないことも確認してください。
